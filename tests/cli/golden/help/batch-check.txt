usage: chronominer batch check [-h] [--input DIR] [--schema NAME] [--batch-ids IDS]
                               [--adopt BATCH_ID | --abandon SUBMISSION_ID] [--wait]
                               [--poll-minutes N] [--wait-hours N] [--formats LIST] [--json]
                               [--settings FILE]

Check the batch submissions found below a folder and write the outputs of every finished batch.

options:
  -h, --help            show this help message and exit

batches:
  --input DIR           folder searched for batch submissions, subfolders included; default: the
                        current directory
  --schema NAME         check only documents extracted with this schema; default: every schema
  --batch-ids IDS       comma-separated batch IDs to check; default: every batch
  --adopt BATCH_ID      record this provider batch for the unresolved submission it belongs to,
                        then finalize it
  --abandon SUBMISSION_ID
                        give up an unresolved or submitted submission: its chunks return to
                        pending and its uploaded files are deleted; a submitted batch is not
                        cancelled
  --wait                check again every --poll-minutes until no batch work is pending, or until
                        --wait-hours have passed
  --poll-minutes N      minutes between two checks with --wait; default: 15
  --wait-hours N        hours after which --wait starts no further check; a running check
                        finishes; default: 50

output:
  --formats LIST        comma-separated formats rendered besides {stem}_output.json and
                        chronominer.sqlite; from csv; default: the formats of the run that
                        submitted each document

run control:
  --json                print one JSON summary line on stdout
  --settings FILE       alternate settings file; default: config/settings.yaml

Without --formats each finalized document is rendered in the formats of the run that submitted it.
With --wait the check repeats every --poll-minutes until no batch work is pending; no check starts
after --wait-hours, but a running one finishes.

Exit codes:
  0    nothing failed
  1    a submission failed or is unresolved; with --wait also when the
       deadline passed with work pending or a check failed with an
       error that is not retried
  2    usage error, a missing folder, a database the store refuses, or
       an --adopt or --abandon that names nothing to act on
  130  interrupted (Ctrl+C or Ctrl+Break)

With --json, stdout carries exactly one JSON summary line on every exit; progress, warnings and
errors go to stderr.
